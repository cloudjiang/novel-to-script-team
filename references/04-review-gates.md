# 业务审核与门控

## 审核流程

1. 业务审核：节奏、冲突、人物一致性、可拍性
2. **跨集内容重复检查**：检查当前集与前一集是否有重复内容
3. **事件完整性检查**：检查当前集是否是一个完整的事件
4. 合规审核：敏感与平台风险
5. 汇总反馈：任一 FAIL 即回改并复审

---

## 四遍修改法

`review-director` 在审核剧本时，应该按照以下四遍修改法进行系统化审核：

### 第一遍：删减冗余（聚焦主线）

**核心任务**：冷酷地删掉所有与主线无关的情节、角色和对话

**检查清单**：
- [ ] 每个情节是否推进主线剧情？
- [ ] 每个角色是否对主线有贡献？
- [ ] 每句对话是否推进剧情、展现人物或制造冲突？
- [ ] 是否有让节奏变慢的部分？

**执行标准**：
- 不为剧情前进服务的无用情节，毫不犹豫地砍掉
- 不为剧情前进服务的无用角色，毫不犹豫地砍掉
- 不为剧情前进服务的无用对话，毫不犹豫地砍掉
- **一句一拳，每一句都在做事**

**FAIL 标准**：
- 如果发现任何与主线无关的情节、角色或对话，必须 FAIL
- 如果发现任何让节奏变慢的部分，必须 FAIL

### 第二遍：强化冲突和爽点（检查戏眼）

**核心任务**：检查每一场戏的"戏眼"是否足够强

**检查清单**：
- [ ] 男女主对峙的台词够不够犀利？
- [ ] 打脸的时刻够不够爽？
- [ ] 冲突的强度够不够高？
- [ ] 爽点的密度够不够大？

**执行标准**：
- 每场戏都要有明确的"戏眼"（最精彩的部分）
- 对峙台词要犀利，打脸时刻要爽
- 冲突强度要高，爽点密度要大
- 在这里进行加强，不要手软

**FAIL 标准**：
- 如果发现任何场戏的"戏眼"不够强，必须 FAIL
- 如果发现对峙台词不够犀利，必须 FAIL
- 如果发现打脸时刻不够爽，必须 FAIL

### 第三遍：修正技术错误（格式、逻辑）

**核心任务**：检查格式、错别字、逻辑漏洞

**检查清单**：
- [ ] 格式是否符合标准？
- [ ] 是否有错别字？
- [ ] 是否有逻辑漏洞？
- [ ] 场景转换是否流畅？
- [ ] 人物行为是否符合设定？

**执行标准**：
- 格式必须符合标准（参考 `references/03-script-writing-standard.md`）
- 不能有错别字
- 不能有逻辑漏洞
- 场景转换必须流畅
- 人物行为必须符合设定

**FAIL 标准**：
- 如果发现任何格式错误，必须 FAIL
- 如果发现任何错别字，必须 FAIL
- 如果发现任何逻辑漏洞，必须 FAIL

### 第四遍：通读检验（观众视角）

**核心任务**：把自己当成观众，快速读一遍，感受节奏和情绪流

**检查清单**：
- [ ] 节奏是否流畅？
- [ ] 情绪是否连贯？
- [ ] 是否有让人觉得无聊的地方？
- [ ] 是否有让人出戏的地方？

**执行标准**：
- 以观众视角快速读一遍
- 感受节奏和情绪流
- 如果中途觉得无聊，那就是还需要修改的地方
- 如果中途觉得出戏，那就是还需要修改的地方

**FAIL 标准**：
- 如果发现任何让人觉得无聊的地方，必须 FAIL
- 如果发现任何让人出戏的地方，必须 FAIL

## 业务审核清单

### 基础审核项
- [ ] 节奏控制：3秒进冲突，每30秒有推进
- [ ] 冲突密度：每集至少2个冲突点
- [ ] 人物一致性：称呼、性格、能力前后统一
- [ ] 钩子强度：集尾悬念足够吸引人
- [ ] 可拍性：所有内容都可视化

### 跨集内容重复检查（新增）
- [ ] 当前集与前一集无重复场景
- [ ] 当前集与前一集无重复剧情点
- [ ] 当前集与前一集无重复对话
- [ ] 当前集与前一集的事件是不同的

**检查方法**：
1. 读取前一集的剧本
2. 提取前一集的场景列表、剧情点列表
3. 对比当前集的场景列表、剧情点列表
4. 如果发现重复，标记具体位置

**FAIL 标准**：
- 如果发现任何重复内容，必须 FAIL
- 必须指出具体的重复位置（如"第2集的场景1与第1集的场景2重复"）
- 必须要求删除或重写重复内容

**示例**：
```
❌ FAIL：跨集内容重复

位置：第2集与第1集
问题：第2集重复了第1集的完整事件"被赶出萧家"
- 第1集：宣布驱逐 → 搜身 → 签字 → 离开
- 第2集：宣布驱逐 → 搜身 → 签字 → 离开（重复）

修改动作：
1. 删除第2集的重复内容
2. 改为新的完整事件，如"拍卖会展示实力"（入场 → 竞拍 → 展示 → 震惊）
```

### 事件完整性检查（新增）
- [ ] 当前集是一个完整的事件（有开始、发展、结束）
- [ ] 当前集没有未完成的剧情线
- [ ] 当前集与下一集的规划无逻辑断层
- [ ] 当前集的事件流程与分集目录一致

**检查方法**：
1. 读取分集目录中当前集的"完整事件流程"
2. 检查剧本是否包含事件的所有步骤
3. 检查事件是否有明确的开始和结束
4. 检查是否有未完成的剧情线

**FAIL 标准**：
- 如果事件不完整（如只有开始没有结束），必须 FAIL
- 如果有未完成的剧情线，必须 FAIL
- 如果与下一集的规划有逻辑断层，必须 FAIL
- 如果事件流程与分集目录不一致，必须 FAIL

**示例**：
```
❌ FAIL：事件完整性

位置：第2集
问题：第2集没有新的完整事件，只是重复了第1集的事件

分集目录规划：
- 第1集：被赶出萧家（完整事件）
- 第2集：拍卖会展示实力（完整事件）

实际剧本：
- 第1集：被赶出萧家 ✓
- 第2集：被赶出萧家（重复）❌

修改动作：
1. 第2集应该是一个新的完整事件
2. 按照分集目录规划，第2集应该是"拍卖会展示实力"
3. 完整事件流程：入场 → 竞拍 → 展示实力 → 震惊全场
```

#### 1. 拆剧总览卡

用于快速了解剧本的整体结构：

### 使用建议

1. **系统化分析**：使用这些工具表可以帮助 `review-director` 系统化地分析剧本
2. **发现问题**：通过填写这些表格，可以快速发现剧本的结构问题、节奏问题、逻辑问题
3. **量化评估**：通过表格可以量化评估剧本的质量（如爽点密度、钩子强度、信息差设计）
4. **详细工具参考**：完整的拆剧工具表存储在 `sources/script-analysis-tools/`

## PASS / FAIL 输出规范

1. PASS：给出通过依据（2-4条）
2. FAIL：必须包含 `位置 + 问题 + 修改动作`

## 常见 FAIL 场景

1. 角色称呼错误
2. 冲突密度不足
3. 情绪曲线断裂
4. 设定前后矛盾
5. **跨集内容重复**（新增）
6. **事件不完整或重复**（新增）

### 跨集内容重复的常见情况
- 相邻两集使用了相同的场景
- 相邻两集重复了相同的剧情点
- 相邻两集的对话高度相似
- 把一个完整事件拆成了两集

### 事件不完整的常见情况
- 事件只有开始没有结束
- 事件的关键步骤缺失
- 事件与分集目录规划不一致
- 事件被不合理地拆分到多集

## Aligner 一致性检查方法论

### 核心理念

Aligner 是质量把关的最后一道防线。在内容写入文档前，必须通过 Aligner 的全面检查，确保：
- 剧情逻辑连贯
- 人物行为一致
- 设定前后统一
- 节奏控制到位
- 格式规范符合

### 双重质量把关体系

**源头把关（剧情拆解阶段）：**
- breakdown-aligner 检查剧情拆解质量
- 验证冲突强度、情绪钩子识别、分集合理性

**输出把关（剧本创作阶段）：**
- webtoon-aligner / doomsday-aligner / xuanhuan-aligner 检查剧本质量
- 验证剧情还原、节奏控制、视觉化风格、一致性

### Aligner 工作流程

```
创作完成 → Aligner 检查 → PASS → 写入文档
                ↓ FAIL
            修改内容 → 重新检查 → 直到 PASS
```

**关键原则：**
- 只有完全符合标准才能输出 PASS 状态
- 发现问题时必须明确指出具体位置和修改方向
- 以大纲/剧情拆解为核心基准进行对比检查

## 检查标准矩阵

### 通用检查维度（适用所有题材）

#### 【维度1】剧情逻辑一致性
**检查对象：** 因果关系、情节发展、冲突递进
- 事件发生顺序是否符合逻辑
- 因果关系是否合理
- 冲突递进是否自然
- 是否有情节断层或突兀感

**基准文档：** 大纲 + 分集目录 + 已创作剧本

#### 【维度2】人物行为一致性
**检查对象：** 性格、能力、对话风格
- 人物性格是否前后统一（不能突然性格崩坏）
- 人物能力是否前后一致（不能忽强忽弱）
- 对话风格是否符合人设
- 人物关系是否符合设定

**基准文档：** 角色档案 + 大纲 + 已创作剧本

#### 【维度3】时间线逻辑一致性
**检查对象：** 事件顺序、时间跨度、位置移动
- 事件发生顺序是否符合逻辑
- 时间跨度是否合理（如"三天后"，后面确实过了三天）
- 人物位置移动是否合理
- 是否出现时间线矛盾

**基准文档：** 大纲 + 已创作剧本

#### 【维度4】节奏控制一致性
**检查对象：** 字数、场景数、结构
- 每集字数是否在 500-800 字范围内
- 场景数是否为 1-3 个（不能超过 3 个）
- 起承转钩结构是否清晰
- 是否 3 秒进冲突，每 30 秒有推进
- 是否有过长的单一画面或拖沓情节

**基准文档：** 改编方法论 + 输出风格指南

#### 【维度5】视觉化风格一致性
**检查对象：** 格式符号、对话长度、动作描写
- 是否使用视觉描述符号（※场景、△动作、【特效】等）
- 对话是否简短有力（不超过 20 字/句）
- 动作描写是否具体可视
- 是否有心理描写过多的问题（必须转化为动作/对话或删除）
- 是否有环境描写、铺垫等漫剧禁忌内容

**基准文档：** 输出风格指南

#### 【维度6】格式规范一致性
**检查对象：** 标题、标记、分隔符
- 是否有集标题（# 第 X 集：<集标题>）
- 是否使用 ※ 标注场景
- 是否使用 --- 分隔场景
- 是否有视觉描述符号说明
- 是否有必要的注释说明

**基准文档：** 剧本模板

#### 【维度7】悬念设置一致性
**检查对象：** 每集结尾悬念
- 每集结尾是否有【卡黑】标记（必须）
- 悬念是否足够吸引人（战斗/身份/危机/真相/情感）
- 是否有平淡收尾的禁忌（"然后主角回去睡觉了"等）
- 悬念设置是否自然，不生硬

**基准文档：** 改编方法论 + 输出风格指南

### 题材特定检查维度

#### 末世重生类特定检查

**【维度8】天灾进程/数值一致性**
- 天灾阶段是否符合大纲中"天灾进程体系"表格的规划
- 天灾降临时机是否合理（如大纲规定第 6-10 集为爆发期）
- 物资数值变化是否有空间面板展示
- 物资数量是否前后统一（如囤了多少粮食、数量是否合理）
- 异能等级进展是否符合大纲规划（如有异能设定）
- 是否出现物资数值自相矛盾（前面说囤了 10 吨，后面变成 1 吨）

**【维度9】金手指规则一致性**
- 金手指的基本规则是否与大纲定义一致（如空间的储物规则、时间静止）
- 空间功能是否前后统一（不能前面说只能储物，后面突然能种植）
- 空间面板显示格式是否统一
- 异能能力边界是否清晰（如有异能设定）
- 是否出现金手指规则自相矛盾

**【维度10】末世重生漫剧禁忌检查**
- 节奏禁忌：囤货过程超过 10 集、连续 3 集没有对比/打脸、连续 5 集没有物资展示
- 逻辑禁忌：空间规则混乱、物资数值忽高忽低、天灾进程不合理
- 情节禁忌：主角圣母心救白眼狼、前世仇人不死或下场不够惨、感情线注水
- 开场禁忌：第 1 集没有前世惨死、第 2 集没有重生囤货、第 10 集末世还没降临
- 高潮禁忌：第 20/40/60 集不够爆
- 圣母心禁忌：主角原谅前世仇人、救助背叛过她的人

#### 玄幻类特定检查

**【维度8】境界体系一致性**
- 主角境界进展是否符合大纲规划
- 境界突破时机是否合理
- 战力数值是否前后统一
- 是否出现境界体系自相矛盾

**【维度9】金手指规则一致性**
- 系统规则是否符合大纲定义并前后统一
- 签到/抽奖/传承等机制是否一致
- 奖励发放是否合理
- 是否出现金手指规则自相矛盾

**【维度10】玄幻漫剧禁忌检查**
- 节奏禁忌：连续 3 集没有打脸、连续 5 集没有境界突破
- 逻辑禁忌：境界体系混乱、战力数值忽高忽低
- 情节禁忌：主角突然圣母心、反派智商下线
- 开场禁忌：第 1 集没有废材设定、第 2 集没有金手指觉醒
- 高潮禁忌：第 20/40/60 集不够爆

#### 网文改编类特定检查

**【维度8】剧情点还原一致性**
- 该集使用的剧情点是否与 plot_breakdown 中分配的一致
- 剧情点的场景、角色、事件是否在剧本中体现
- 是否遗漏了应该出现的剧情点
- 是否添加了 plot_breakdown 中没有的重大情节

**【维度9】剧情点使用一致性**
- 该集使用的剧情点编号是否正确（如第 5 集应该用【剧情 X】到【剧情 Y】）
- 是否使用了其他集的剧情点
- 是否重复使用了已在前面集数使用过的剧情点
- 剧情点的情绪钩子类型是否在剧本中体现

**【维度10】跨集连贯性**
- 本批次第一集与上一批次最后一集的剧情衔接是否自然
- 人物状态是否连续（如上集受伤，本集不能突然痊愈）
- 场景转换是否合理（如上集在 A 地，本集在 B 地，需要交代移动）
- 时间线是否连贯（如上集"三天后见"，本集确实过了三天）
- 是否有情节断层或突兀感

## 爽点分布验证

### 付费节点检查（关键）

**第 10 集（免费段结尾）：**
- 是否有最爽悬念，能否吸引付费
- 身份/能力即将揭晓但被截断
- 观众被吊在最高点

**第 20 集（第一大高潮）：**
- 是否有超级爆点
- 主角第一次大规模能力展示
- 反派第一次惨败

**第 30 集：**
- 是否有大爽点
- 舞台升级或新势力登场

**第 40 集（第二大高潮）：**
- 是否有超级爆点
- 核心能力/身份曝光
- 多线汇聚

**第 50 集：**
- 是否有大爽点
- 终极危机预警

**第 60 集（终极高潮）：**
- 是否有超级爆点
- 终极对决 + 情感收束

### 日常爽点检查

- 每 2-3 集是否有小爽点（对比场景/能力展示/日常打脸）
- 每 5 集是否有中爆点（反派出现/复仇打脸/能力升级）
- 是否有连续 5 集没有爽点（节奏错误）

## 质量把关流程

### 阶段 1：剧情拆解质量检查（breakdown-aligner）

**触发时机：** 每完成 6 章剧情拆解时

**检查内容：**
- 冲突强度是否准确识别
- 情绪钩子是否精准提取
- 分集标注是否合理
- 剧情点数量是否适中（每集 2-4 个）

**输出：** PASS/FAIL + 问题清单

### 阶段 2：单集剧本一致性检查（webtoon/doomsday/xuanhuan-aligner）

**触发时机：** 每完成一批次剧本创作时

**检查内容：**
- 剧情还原准确性
- 节奏控制到位性
- 视觉化风格统一性
- 人物行为一致性
- 时间线逻辑合理性
- 格式规范符合性
- 悬念设置自然性
- 题材特定要求符合性

**输出：** PASS/FAIL + 详细问题清单

### 阶段 3：总复核（review-director）

**触发时机：** 每完成一集或一批次后

**检查内容：**
- 业务审核：节奏、冲突、人物一致性、可拍性
- 合规审核：敏感内容、平台风险
- 强制命令执行：grep 检查乱码和称呼错误

**输出：** PASS/FAIL + 汇总反馈

## 常见问题与解决方案

### 问题 1：连续 FAIL 无法通过

**原因：** 修改方向不明确，反复修改同一问题

**解决方案：**
1. 仔细阅读 Aligner 反馈的具体位置和修改动作
2. 对照基准文档（大纲/角色档案/剧情拆解）进行修改
3. 修改后重新检查，确保问题已解决

### 问题 2：PASS 后发现新问题

**原因：** Aligner 检查维度有限，某些问题未覆盖

**解决方案：**
1. 补充 Aligner 检查维度
2. 增加人工复核环节
3. 建立问题反馈机制，持续优化 Aligner

### 问题 3：检查时间过长

**原因：** 逐集检查耗时，批次过大

**解决方案：**
1. 控制批次大小（建议每批次 5 集）
2. 优化 Aligner 检查逻辑，提高效率
3. 并行检查多个维度

## 逻辑一致性检查增强

### 检查维度

#### 【人物关系一致性】

**称呼一致性**：
- 人物之间的称呼是否符合关系设定
- 称呼是否与分析报告中的"称呼规范表"一致
- 称呼是否随剧情发展合理变化

**常见错误**：
- 母亲称儿子为"弟弟"
- 陌生人之间使用亲密称呼
- 关系破裂后仍使用亲密称呼

**人物关系逻辑**：
- 人物之间的关系是否清晰明确
- 关系变化是否有合理的剧情推动
- 是否存在关系矛盾

**人物行为一致性**：
- 人物行为是否符合性格设定
- 人物动机是否合理
- 是否存在OOC（人设崩塌）

#### 【场景关系一致性】

**场景连贯性**：
- 场景切换是否合理
- 场景之间的时间、空间关系是否清晰
- 是否存在场景跳跃（无过渡）

**场景道具一致性**：
- 道具是否在合理的场景中出现
- 道具的状态是否前后一致
- 是否存在道具凭空出现/消失

**场景氛围一致性**：
- 场景氛围是否符合剧情需要
- 同一场景在不同时间的氛围变化是否合理
- 是否存在氛围突变（无铺垫）

#### 【镜头关系一致性】

**镜头逻辑**：
- 镜头切换是否符合视觉逻辑
- 是否存在镜头跳跃（违反180度法则）
- 镜头运动是否合理

**视角一致性**：
- 视角是否统一（主观/客观）
- 视角切换是否有明确提示
- 是否存在视角混乱

**时空连续性**：
- 镜头之间的时间关系是否清晰
- 是否存在时间跳跃（无提示）
- 闪回镜头是否有明确标识

#### 【时间线一致性】

**时间锚点**：
- 关键时间点是否明确
- 时间流逝是否合理
- 是否存在时间矛盾（如倒计时字幕错误）

**事件顺序**：
- 事件发生顺序是否合理
- 因果关系是否清晰
- 是否存在逻辑倒置

### 审核流程增强

**原有流程**：
```
强制检查 → 对比审核 → 业务审核 → 合规审核
```

**增强后流程**：
```
强制检查 → 逻辑一致性检查 → 对比审核 → 业务审核 → 合规审核
```


## 质量标准总结

### A 级标准（必须达到）

- 剧情逻辑连贯，无明显漏洞
- 人物行为一致，性格不崩坏
- 节奏控制到位，起承转钩清晰
- 格式规范符合，视觉化风格统一
- 每集结尾有【卡黑】悬念
- 逻辑一致性检查全部PASS

### B 级标准（建议达到）

- 爽点分布合理，付费节点精准
- 时间线逻辑严密，无矛盾
- 伏笔埋设与回收完整
- 题材特定要求符合（境界体系/天灾进程/剧情点还原）

### C 级标准（优化方向）

- 对话精炼有力，无废话
- 动作描写具体可视
- 情绪渲染到位，氛围感强
- 创新元素丰富，避免套路化

## 制片收本评分表（2026行业标准）

> 来源：018-编辑/制作人审核标准、020-收本评分表（2026-03-12 收编）

### 100分制评分维度

| 维度 | 分值 | 核心评估点 |
|------|------|-----------|
| 合规性 | 25分 | 红线零容忍、备案信息一致、价值观正向 |
| 节奏与钩子 | 20分 | 黄金3秒/30秒法则、每集结尾留钩、每3分钟一个情绪峰值 |
| 爽点与人设 | 20分 | 人设出场即立住、情感共鸣强、爽而有度 |
| 拍摄可行性 | 15分 | 场景集中易拍、演员可控、预算友好 |
| 商业潜力 | 20分 | 付费节点精准、题材匹配平台偏好、IP衍生空间 |

### 定级标准

- S级（85+）：优先排期，平台重点推荐
- A级（70-84）：正常排期，可上线
- B级（60-69）：需修改后复审
- C级（60以下）：退稿

### 选本三步筛选法

1. **初筛（10分钟/本）**：看大纲+前10集
   - 核心冲突、主线、人设、结局是否闭环
   - 前3集是否有大事件，每集结尾是否有钩子
   - 淘汰标准：踩红线、节奏拖沓、场景复杂、人设模糊
2. **中筛（30分钟/本）**：深度评估"三力"
   - 留存力：钩子密度、悬念质量
   - 付费力：付费节点设计、情绪峰值分布
   - 可拍力：场景数量、特效需求、演员规模
3. **终筛（1小时/本）**：全本通读
   - 逻辑闭环检查、人设一致性、合规复核
