## 1. 帧图生成失败

### 问题表现

```bash
python scripts/generate_image.py \
  --prompt-file "outputs/块宇宙短片/storyboard/ep01/03-frame-requests.md" \
  --output-dir "outputs/块宇宙短片/images/frames/ep01" \
  --prefix frame

# 输出：
✗ [frame-F01.png] API 错误: 401 Unauthorized
```

### 可能原因

1. **API key 未配置或无效**
2. **帧图提示词格式错误**
3. **参考图路径错误**
4. **网络连接问题**

### 解决方案

#### 1.1 检查 API key

```bash
# 检查 .env 文件是否存在
ls -la .env

# 检查 API key 是否配置
grep "NANO_BANANA_API_KEY\|NANO_BANANA_BASE_URL" .env

# 如果没有，添加 API key
printf "NANO_BANANA_API_KEY=your_api_key_here\nNANO_BANANA_BASE_URL=https://your-provider.example/v1\n" >> .env
```

#### 1.2 验证帧图提示词格式

帧图提示词必须符合以下格式：

```markdown
## 帧图 F01：P16b 穿越闪白 首帧

**参考图**：人物 01a

[静态画面描述，不含动态内容]
```

**常见错误**：
- ❌ 标题格式错误：`### 帧图 F01`（应该是 `##`）
- ❌ 缺少参考图标记：没有 `**参考图**：` 行
- ❌ 包含动态描述：`归档者伸手触碰镜面`（应该是静态姿态）

#### 1.3 检查参考图路径

```bash
# 检查参考图是否存在
ls -la outputs/块宇宙短片/images/characters/char-01a.png

# 如果不存在，先生成资产图
python scripts/generate_image.py \
  --prompt-file "outputs/块宇宙短片/assets/character-prompts.md" \
  --output-dir "outputs/块宇宙短片/images/characters" \
  --prefix char
```

#### 1.4 重试机制

脚本默认重试 2 次，可增加重试次数：

```bash
python scripts/generate_image.py \
  --prompt-file "outputs/块宇宙短片/storyboard/ep01/03-frame-requests.md" \
  --output-dir "outputs/块宇宙短片/images/frames/ep01" \
  --prefix frame \
  --max-retries 5
```

## 2. 模式选型错误

### 问题表现

审核报告显示：

```
❌ 业务审核：FAIL

**问题1**：模式选型不合理
- 位置：P16b 提示词
- 当前问题：使用了 T2V 模式，但这是闪白硬切场景，需要精确控制开场构图
- 修改方向：应使用 I2V-首帧 + 多参考 模式
```

### 可能原因

1. **决策树应用错误**
2. **剧情点特征判断错误**
3. **模式优先级理解错误**

### 解决方案

#### 2.1 重新应用决策树

按优先级从高到低判断：

```
1. 需要精确 A→B 画面过渡（连续动作、无缝转场）？
   → 首尾帧 + 多参考

2. 需要精确控制开场构图（硬切换景别/机位）？
   → I2V-首帧 + 多参考

3. 涉及多角色/场景一致性？
   → 多参考
   - 追加判断：≥ 8s 且多时段画面差异大？
     → 需要分镜参考图

4. 纯氛围/概念镜头？
   → T2V

5. 默认
   → 多参考
```

#### 2.2 常见场景的正确模式

| 场景特征 | 正确模式 | 错误模式 | 原因 |
|---------|---------|---------|------|
| 闪白硬切进入新场景 | I2V-首帧 + 多参考 | T2V | 需要精确控制闪白后的第一帧构图 |
| 镜头从第1层连续后拉至第2层 | 首尾帧 + 多参考 | 多参考 | 需要 A→B 丝滑过渡 |
| 8s 多时段画面差异大 | 多参考 + 分镜参考图 | 多参考 | 需要引导各时段画面 |
| 纯环境无人物 | T2V | 多参考 | 无需人物一致性 |

#### 2.3 修改模式标注

在 `02-seedance-prompts.md` 中找到对应提示词，修改模式标注：

```markdown
# 修改前
**生成模式**：T2V | **选型理由**：纯环境氛围镜头

# 修改后
**生成模式**：I2V-首帧 + 多参考 | **选型理由**：闪白硬切，需精确控制穿越瞬间的开场构图
**帧图需求**：首帧（F01）
```

同时更新引用行：

```markdown
# 修改前
**时长**：2s | **引用**：@图片1（归档者）

# 修改后
**时长**：2s | **引用**：@图片1（归档者）, @图片21(首帧)
```

## 3. 引用配额超限

### 问题表现

审核报告显示：

```
❌ 业务审核：FAIL

**问题1**：引用配额超限
- 位置：P24 提示词
- 当前问题：I2V-首帧 + 多参考 模式，首帧图 1 张 + 角色/场景参考图 9 张 = 10 张，超过 9 张上限
- 修改方向：减少参考图数量或改用其他模式
```

### 可能原因

1. **模式叠加时未计算配额**
2. **分镜参考图过多**
3. **引用了不必要的参考图**

### 解决方案

#### 3.1 配额计算规则

| 模式 | 配额占用 | 剩余配额 |
|------|---------|---------|
| T2V | 0 张（不需要参考图） | 9 张 |
| I2V-首帧 | 1 张首帧图 | 8 张 |
| 首尾帧 | 2 张（首帧 + 尾帧） | 7 张 |
| 多参考 | N 张角色/场景参考图 | 9 - N 张 |
| I2V-首帧 + 多参考 | 1 张首帧图 + N 张参考图 | 9 - 1 - N 张 |
| 首尾帧 + 多参考 | 2 张（首帧 + 尾帧）+ N 张参考图 | 9 - 2 - N 张 |

#### 3.2 减少参考图数量

**策略1**：移除不必要的参考图

```markdown
# 修改前（10 张，超限）
**引用**：@图片1（归档者）、@图片2（昨天的他）、@图片3（妻子）、@图片4（三角形回路）、@图片5（菱形回路）、@图片6（五边形回路）、@图片12（工作室）、@图片13（桌面俯拍）、@图片14（镜子空间）, @图片21(首帧)

# 修改后（9 张，合规）
**引用**：@图片1（归档者）、@图片3（妻子）、@图片6（五边形回路）、@图片12（工作室）、@图片14（镜子空间）, @图片21(首帧)
```

**策略2**：改用其他模式

```markdown
# 如果不需要精确控制开场构图，改用多参考模式
**生成模式**：多参考 | **选型理由**：多角色/场景一致性控制
**引用**：@图片1（归档者）、@图片2（昨天的他）��@图片3（妻子）、@图片4（三角形回路）、@图片5（菱形回路）、@图片6（五边形回路）、@图片12（工作室）、@图片13（桌面俯拍）、@图片14（镜子空间）
```

#### 3.3 分镜参考图优化

如果多时段画面差异不大，不需要分镜参考图：

```markdown
# 修改前（需要 3 张分镜参考图）
**生成模式**：多参考 | **选型理由**：8s多时段画面差异大，需分镜参考图引导
**帧图需求**：分镜参考图（F03, F04, F05）

# 修改后（不需要分镜参考图）
**生成模式**：多参考 | **选型理由**：多角色/场景一致性控制
```

## 4. 帧图描述包含动态内容

### 问题表现

审核报告显示：

```
❌ 业务审核：FAIL

**问题1**：帧图描述包含动态内容
- 位置：03-frame-requests.md 帧图 F01
- 当前问题：描述中包含"归档者伸手触碰镜面"，这是动态动作
- 修改方向：改为静态姿态描述
```

### 可能原因

1. **误将动作描述写入帧图**
2. **未理解"静态单帧画面"的含义**

### 解决方案

#### 4.1 静态 vs 动态描述对比

| 动态描述（❌ 错误） | 静态描述（✅ 正确） |
|------------------|------------------|
| 归档者伸手触碰镜面 | 归档者右手缓缓伸出，指尖触碰镜面 |
| 妻子转身走入更深镜子 | 妻子背对镜头，身体侧向右侧 |
| 镜头从侧脸推向窗外 | 归档者侧脸特写，窗外夜色在背景中 |
| 倒影从四面涌现 | 多个归档者倒影分布在四周镜面中 |

#### 4.2 帧图描述模板

```markdown
## 帧图 F01：[对应剧情点] [帧图类型]

**参考图**：[引用的角色/场景]

[人物姿态]：[具体描述人物的静态姿态、表情、手势]
[构图]：[画面构图方式，如中央构图、三分法]
[光影]：[光线类型、方向、色调]
[景深]：[浅景深、深景深]
[风格]：[低饱和冷蓝灰调、轻微胶片颗粒等]
```

#### 4.3 修改示例

```markdown
# 修改前（包含动态）
## 帧图 F01：P16b 穿越闪白 首帧

归档者伸手触碰镜面，镜面出现涟漪。

# 修改后（纯静态）
## 帧图 F01：P16b 穿越闪白 首帧

**参考图**：人物 01a

以归档者为参考的中景画面。归档者右手缓缓伸出，指尖触碰墙上镜面，
镜面出现同心圆涟漪从触碰点向外扩散。冷白光照亮手指和镜面。
中央构图，浅景深，镜面居画面中心。低饱和冷蓝灰调，轻微胶片颗粒。
```

## 5. 素材对应表错误

### 问题表现

审核报告显示：

```
❌ 业务审核：FAIL

**问题1**：素材对应表不完整
- 当前问题：提示词中引用了 @图片21，但素材对应表中没有此条目
- 修改方向：在素材对应表中添加 @图片21 的映射
```

### 可能原因

1. **帧图生成后未更新素材对应表**
2. **素材对应表编号错误**
3. **帧图引用编号与对应表不一致**

### 解决方案

#### 5.1 检查素材对应表完整性

素材对应表应包含：
- 人物参考（@图片1-N）
- 物品参考（@图片N+1-M）
- 场景参考（@图片M+1-K）
- 帧图（@图片K+1-L）

#### 5.2 添加帧图条目

在素材对应表末尾添加帧图条目：

```markdown
| @图片21 | 帧图（首帧） | P16b 穿越闪白 首帧（F01） | images/frames/ep01/frame-F01.png |
| @图片22 | 帧图（首帧） | P17 进入镜子空间 首帧（F02） | images/frames/ep01/frame-F02.png |
| @图片23 | 帧图（分镜） | P24 倒影洪流 0-3s 分镜（F03） | images/frames/ep01/frame-F03.png |
```

#### 5.3 更新说明部分

```markdown
**说明**：
- @图片1-3 为人物参考，@图片4-11 为物品参考，@图片12-20 为场景参考
- @图片21-36 为帧图（首帧/尾帧/分镜参考图），详见 03-frame-requests.md
- 每条提示词最多引用 9 张图片（平台限制）
```

## 6. 跨集帧图引用问题

### 问题表现

```
EP02 需要引用 EP01 的帧图 F01，但 generate_image.py 找不到该文件
```

### 可能原因

1. **帧图按集组织，不支持跨集引用**
2. **--image-base-dir 未包含其他集的帧图目录**

### 解决方案

#### 6.1 当前限制

帧图按集组织，默认不支持跨集引用：

```
images/
├── frames/
│   ├── ep01/
│   │   └── frame-F01.png
│   └── ep02/
│       └── frame-F01.png  # EP02 的 F01，与 EP01 的 F01 不同
```

#### 6.2 临时解决方案

如果确实需要跨集引用，手动复制帧图：

```bash
# 将 EP01 的帧图复制到 EP02
cp outputs/块宇宙短片/images/frames/ep01/frame-F01.png \
   outputs/块宇宙短片/images/frames/ep02/frame-F01-from-ep01.png
```

在 EP02 的 `03-frame-requests.md` 中引用：

```markdown
## 帧图 F01：P01 开场 首帧（复用 EP01 F01）

**参考图**：人物 01a

[与 EP01 F01 相同的描述]
```

#### 6.3 长期解决方案

如果经常需要跨集引用，建议：
1. 将可复用的帧图提升为"资产图"，放入 `images/characters/` 或 `images/scenes/`
2. 在 `character-prompts.md` 或 `scene-prompts.md` 中添加对应条目

## 7. API 调用失败

### 问题表现

```bash
✗ [frame-F01.png] API 错误: 500 Internal Server Error
✗ [frame-F02.png] API 错误: Timeout
```

### 可能原因

1. **API 服务器故障**
2. **网络连接问题**
3. **请求超时**
4. **提示词过长**

### 解决方案

#### 7.1 检查 API 服务状态

```bash
# 测试 API 连接
curl -I "$NANO_BANANA_BASE_URL/chat/completions"
```

#### 7.2 增加超时时间

```bash
python scripts/generate_image.py \
  --prompt-file "outputs/块宇宙短片/storyboard/ep01/03-frame-requests.md" \
  --output-dir "outputs/块宇宙短片/images/frames/ep01" \
  --prefix frame \
  --timeout 600  # 增加到 10 分钟
```

#### 7.3 减少提示词长度

如果提示词过长，精简描述：

```markdown
# 修改前（过长）
以归档者为参考的中景画面。归档者右手缓缓伸出，指尖触碰墙上镜面，
镜面出现同心圆涟漪从触碰点向外扩散。冷白光照亮手指和镜面。
中央构图，浅景深，镜面居画面中心。低饱和冷蓝灰调，轻微胶片颗粒质感，
超写实风格，电影摄影质感。背景是工作室环境，桌面上有多个回路装置。

# 修改后（精简）
归档者中景，右手指尖触碰镜面，镜面涟漪扩散。冷白光，中央构图，
浅景深。低饱和冷蓝灰调，轻微胶片颗粒。
```

#### 7.4 分批生成

如果批量生成失败，尝试单个生成：

```bash
# 单个生成
python scripts/generate_image.py \
  --prompt "归档者中景，右手指尖触碰镜面..." \
  --output-dir "outputs/块宇宙短片/images/frames/ep01" \
  --prefix frame
```

## 快速诊断流程

遇到问题时，按以下顺序排查：

```
1. 检查 API key 是否配置
   ↓
2. 检查文件格式是否正确（03-frame-requests.md）
   ↓
3. 检查参考图是否存在
   ↓
4. 检查模式选型是否合理
   ↓
5. 检查引用配额是否超限
   ↓
6. 检查帧图描述是否为静态
   ↓
7. 检查素材对应表是否完整
   ↓
8. 检查网络连接和 API 服务状态
```
